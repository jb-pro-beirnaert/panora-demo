# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

Specifications are in `specs/` (written in French). Implementation proceeds version by version (V1 → V11), one git branch per version created from the previous one; what each version did and how is written in `docs/versions/vNN-*.md`. Each version spec lists the services it touches, its scope, its acceptance criteria, and what is explicitly out of scope. Before implementing anything, read `specs/00-overview.md`, `specs/00-demo-data-and-scenarios.md` and the spec for the version being built. Do not build features from a later version early.

The project is a demo built for a job application to Panora (an insurance-brokerage AI startup): a claim e-mail reaches a brokerage, three AI agents analyze it, check coverage at the insurer through an MCP connector, and a broker approves the proposed action before it is executed and audited.

## Non-negotiable conventions

- **Specs are in French; all code is in English**: file names, identifiers, tables, columns, routes, MCP tools, events, log messages, commits. Use the glossary in `specs/00-overview.md` §3 (e.g. cabinet → `Brokerage`, contrat → `Policy`, garantie → `Coverage`, franchise → `deductible`, plafond → `limit`, sinistre → `Claim`, dossier → `Case`).
- **One database per service**: no service reads another service's database. Data crosses service boundaries only over HTTP/MCP.
- **Zod everywhere**: every payload crossing a service boundary (request, callback, agent output) is validated by a schema from `packages/shared` (`@demo/shared`).
- **Least privilege**: agents only get read tools. Every write (e.g. MCP `file_claim`) happens in a code step after human approval, using the MCP `write` token.
- **Fictional data only**, generated by `packages/world-generator` with a fixed seed (reproducible). The simulator and the evals use the same library.
- **No Docker volumes**: Postgres runs on `tmpfs`, Redis without persistence. Every `npm run dev` starts from empty databases that the simulator re-seeds automatically.
- **Agent prompts: one prompt per agent, in English** (`apps/agents/src/mastra/prompts/`), never duplicated per language. Structured outputs use language-neutral English values (`covered`, `not_covered`, `uncertain`, `request_documents`…). Language rules: client e-mail draft in the inbound e-mail's language; internal note in `Brokerage.locale`; clause citations copied in their original language. Expected languages are passed explicitly in the agent input.
- **UI text is never hard-coded**: next-intl with `apps/web/messages/fr.json` / `en.json` (English keys like `inbox.title`). `AgentStep`, `AuditLog` and agent events are stored as `type` + `params` and rendered via translation keys, so the timeline follows the UI language. Free text from agents (drafts, notes, clause excerpts) is shown as-is with a language badge. A test checks that `fr.json` and `en.json` have identical keys.
- **Environment variables live in a single root `.env` file** (gitignored), never hard-coded and never in per-app env files. Claude cannot read or edit `.env`: it only maintains `.env.example` (every variable, grouped by service, with a short comment and a safe placeholder/default). Whenever a change adds, renames, removes or changes the default of a variable, update `.env.example` and **explicitly tell the user which lines to add or change in their `.env`** in the final message.
- `AuditLog` is append-only: no update or delete route.
- `/admin/*` routes (seed, reset) exist only with `DEMO_MODE=true` and require an admin token.

## Stack

TypeScript everywhere (Node.js 24), npm workspaces + Turborepo. Next.js App Router + Tailwind + shadcn/ui + next-intl; NestJS + Prisma + PostgreSQL; BullMQ + Redis; Mastra in framework mode (own server) with Claude models (Qwen via Ollama in V8); MCP server using the official TypeScript MCP SDK over Streamable HTTP; Langfuse (Cloud in V5, self-hosted in V6); `@faker-js/faker`; Docker Compose (`compose.yaml`); GitHub Actions.

## Architecture

"Core orchestrates, Mastra thinks, the MCP server fetches insurer data; the simulator plays the outside world."

| Service | Dir | Port | DB |
| --- | --- | --- | --- |
| Web (Next.js) | `apps/web` | 3000 | — |
| Core API (NestJS) | `apps/core-api` | 3001 | `core` |
| MCP extranet server | `apps/mcp-extranet` | 3002 | `extranet` |
| Simulator | `apps/simulator` | 3003 | — |
| Mastra server | `apps/agents` | 4111 | `agents` (workflow snapshots) |
| Postgres / Redis / Langfuse (self-hosted) | `compose.yaml` | 5432 / 6379 / 3100 | — |

`infra/postgres/init.sql` creates the three logical databases. Core and the MCP server apply Prisma migrations on startup; Mastra creates its tables on first use.

Request flow for one e-mail:

1. Simulator → `POST /emails` on Core → creates a `Case` and enqueues a `process-email` BullMQ job.
2. The worker starts the Mastra workflow, stores `workflowRunId`, and **returns immediately** (never waits for the workflow).
3. Workflow `process-email`: `prepare` (code) → `triage` (`triageAgent`, light model, tool `find_client` → Core) → if not a claim, `classify` and stop → sub-workflow `handle-claim`: `analyze-coverage` (`coverageAgent`, strong model, 5 MCP read tools) → `dountil` loop of `draft` (`draftingAgent`, no tools) + `approval` (`suspend()`, snapshot persisted in `agents` DB) → `execute` (code; `file_claim` via MCP write token, otherwise status `ready_to_send`).
4. Mastra reports progress to Core via service-token callbacks on `/internal/cases/:id/...` (steps, proposed-action, executed-action, agent-events); Core pushes them to the UI over SSE `GET /realtime`. Callbacks for a case that no longer exists (after a reset) are ignored.
5. Broker decides via `POST /cases/:id/decision` → `resume-workflow` job → Mastra resumes with `{ approved, comment?, brokerId }`. A rejection comment is fed back to `draftingAgent`. Resume must survive a Mastra restart.

MCP server: read tools `search_policy`, `get_policy`, `list_coverages`, `read_clause`, `get_claim_history`; write tool `file_claim` (V2). Tokens are `read` or `write` and carry a `brokerCode` for brokerage isolation (other brokerage's policy → "access denied"). Tool descriptions and error messages are written for an LLM (e.g. suggest the next tool to try). Every call is logged in `CallLog`. The insurer's view of a policy can differ from the brokerage's `knownStatus` — this mismatch (scenario 2, terminated policy) is the flagship demo case.

Core keeps business-level audit rows; Langfuse keeps technical detail (prompts, tokens, cost). Tracing failures must never break the workflow.

The scenario catalog (expected verdicts, alerts, actions, ground truth) is in `specs/00-demo-data-and-scenarios.md`; evals (`evals/`, V7) score agents against that ground truth, per language.

## Commands (planned, per `specs/00-overview.md` §5)

These do not exist until the corresponding version is implemented.

- `npm install` — single install at the root (one lockfile, shared `node_modules`).
- `npm run dev` — recreate empty Postgres (+ Redis from V3) and start all apps in watch mode.
- `npm run dev:langfuse` — same, with self-hosted Langfuse (Compose profile `langfuse`, V6).
- `npm run infra:down` — stop and remove containers.
- `npm run build` / `lint` / `typecheck` / `test` — across all workspaces via Turborepo.
- `npm run dev -w apps/core-api` — run a script in a single workspace.
- `npm run token -w apps/mcp-extranet -- read DLM-075` — print an MCP extranet token (`read` or `write`, per brokerage), e.g. for the MCP inspector (V2).
- `npm run gen:evals -- --seed 7 --count 60` — generate the eval dataset into `evals/datasets/` (V7).
- `npm run evals` (`-- --matrix` for model comparison, V8) — run evals, write JSON + Markdown report, push scores to Langfuse.
- `npm run start:docker` — full stack in containers (Compose profile `apps`, V11). Docker images are built per app via `turbo prune --docker`.

CI (V7): `.github/workflows/ci.yml` (lint, typecheck, unit + integration tests) and `evals.yml` (on PRs touching `apps/agents`; fails if a score drops below its threshold or by more than 2 points vs. main).
